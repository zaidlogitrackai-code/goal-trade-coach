- Daily trading status is computed only in `src/lib/trading-status.ts` (pure, tested) — one source of truth for dashboard and trade form.
- Every "today / this week (from Monday) / this month" boundary, day key and reminder time comes only from pure `src/lib/trading-day.ts`, in trading_settings.timezone (safeTz falls back to Asia/Riyadh) — the server runs in UTC and the phone can travel, so limits, alerts, plans and once-a-day locks must share the trader's own calendar.
- Typed numbers go through `parseDecimal` (`src/lib/num.ts`, used by NumberField) and money at risk only through `riskUsd`/contract size in `src/lib/trade-idea.ts` — an Arabic-region iPhone types '١٫٠٨', and a raw price distance is not dollars.
- Emotion words and the revenge window come only from pure `src/lib/emotions.ts`: `REVENGE_WINDOW_MIN(settings)` = max(30, cooldown_minutes), checked with `inRevengeWindow`, in the discipline score, focus insights and (later) the gate — they must agree on what "right after a loss" means.
- Symbols are read from free text only by `detectSymbols` (`src/lib/market-symbols.ts`): Arabic aliases match whole words (optional و/ب/ل/ال prefixes) after normalising alef/ة/tatweel, and there is no bare 'ين' — it hides inside وين/الحين/بين and pulled USDJPY charts into gold analyses.
- App data is read/written from the browser Supabase client under owner-only RLS; protected pages live under `src/routes/_authenticated/` (ssr: false) — single-user personal app, no server functions needed yet.
- AI features (analyst, coach, report summary) run only through authenticated server functions in `src/lib/ai.functions.ts`, using `src/lib/ai.server.ts` (gateway call, streamed to final text) — keeps the API key server-side and grounds replies in the user's own data.
- Performance/discipline/report numbers come from pure helpers in `src/lib/stats.ts` — one calculation shared by every page.
- AI-proposed changes are structured actions (`src/lib/agent-actions.ts`) validated with zod and executed in the browser; سَنَد auto-runs them except DESTRUCTIVE actions (deletes) and any loosening of a limit, which always wait for a click (owner decision, docs/decisions/sanad-steps.md) — full control without silent data loss.
- The daily morning message is generated lazily on the first visit of the day (`morningGreeting`, unique per user/day) — no scheduler needed for a single-user app.
- Mobile navigation uses four fixed primary destinations plus a complete “more” sheet — stable icon positions reduce cognitive load while preserving every route.
- AI-created trades are de-duplicated via `src/lib/trade-dedupe.ts` (symbol+direction+entry, 24h) and count as closed only by status 'closed' or an exit price (`isClosedUpload` in agent-actions.ts; an explicit 'open' wins) — re-uploading the same broker screenshot must never double-count, and floating P&L on an MT5 Trade tab is not a result.
- Bulk reads that feed money numbers (trades, closed P&L) page through pure `src/lib/fetch-all.ts` and throw on error; the capital ledger is read only via `readCapitalRow` (queries.ts, oldest row, warns on duplicates) — PostgREST silently caps a response at 1000 rows, and a balance missing its losses loosens every % limit.
- Risk alerts come only from pure `src/lib/risk-watch.ts`, run client-side every minute by `RiskWatcher` and de-duplicated via `notifications.dedupe_key` (an insert's 23505 means already delivered; any other error is logged and toasted, and a reminder only advances once delivered) — in-app only (user chose no push), one collapsed toast per run, so alerts never repeat or vanish.
- Risk management page is a chat with the risk guardian (shared SessionAgent with title/mode props, thread "حارس المخاطر"; coachReply mode=risk adds RISK_MODE); daily morning note via riskMorning deduped by notifications.dedupe_key; RiskWatcher also posts alerts into that thread — one agent chat per area keeps everything conversational.
- Discipline streak = login streak (user_visits, one row per day written silently by VisitRecorder) computed only in pure src/lib/streak.ts loginStreak (Mon–Fri, tz-aware); shown only on the discipline page and in AI context.
- Performance dashboard metrics (period windows, drawdown, R, streaks, calendar) come only from pure `src/lib/perf.ts` (tested) — keeps the numbers tz-correct and consistent.
- Each area (risk, strategies, discipline, analyst) is a dedicated agent chat thread via SessionAgent + coachReply mode (risk|strategy), hidden from the coach thread list — keeps everything conversational.
- Daily plan (target/trades/stop/max loss) lives in daily_plans (one row per day, revised_count tracks mid-day changes); greed/breach checks only in pure src/lib/daily-plan.ts — the discipline agent reads them from context.
- The agent persona is named سَنَد; every delete action is listed in DESTRUCTIVE so it always waits for its own click (never auto-run, never part of «وافق على الكل») — prevents accidental data loss in auto mode.
- Appearance (فاتح | داكن | تلقائي) resolves only in pure `src/lib/theme.ts`; the html `light` class is the one runtime truth (`dark:` = not light), set before first paint by `THEME_BOOT_SCRIPT` (generated from theme.ts, also follows the iPhone live), with meta theme-color and Sonner following it — no theme flash, and status bar, toasts and page never disagree.
- Phone UI goes through shared pieces: sheets via `ResponsiveSheet` (vaul drawer under 768px, Dialog above; a `<form>` body when it saves), every "are you sure" via `ConfirmDialog` (never window.confirm/prompt), conversation deletes via `DeleteThreadButton` (`deleteWithUndo`: «تراجع» window, commits when the app is left), bell rows route only via pure `src/lib/notification-target.ts`; Button/Input/Checkbox get 44pt floors under `pointer-coarse:` and `hover:` only fires on hover devices — iPhone-first: native sheets, no English browser prompts, no data lost to a stray tap.
- Query defaults: staleTime 60s, no focus refetch, polling paused when the tab is hidden; backdrop blur only ≥768px — keeps the mobile app smooth.
- Live market data for the nine instruments comes only from `src/lib/market.server.ts`: TradingView public scanner for price/indicators (matches the chart), Yahoo candles shifted onto that price for structure; analyst-only, no on-screen ticker — free, no key.
- Notifications are hidden (`dismissed`), never deleted — by the bell's clear buttons and سَنَد's delete_notifications; the bell filters to today in its SELECT — the rows double as once-only locks (`dedupe_key`/`day`) for alerts and the daily AI messages, so deleting them regenerates duplicates.
- Chat sends go through `src/lib/chat-retry.ts` (`sendReliably`: on a network drop it watches the thread for the reply, resends once only if the message never arrived; coachReply runs its AI work under `keepAlive` (waitUntil via `src/lib/request-context.server.ts`, set in `src/server.ts`) so replies finish after a disconnect) and store only a small thumbnail in `coach_messages.image` — phone connections drop and must never lose or duplicate a message.
- Strategy training examples live in strategy_examples and are injected into every agent's context via buildContext; training progress score only in pure src/lib/training.ts — one learned profile shared by all agents.
- Money limits are stored also as % of balance (trading_settings.limits_pct) and turned into dollars only by src/lib/effective-limits.ts using the live capital balance — limits must follow deposits/corrections/P&L.
- Analyst paper self-test (10-min virtual scalps) runs client-side in `paper-test-panel.tsx` with pure `src/lib/paper-test.ts`; results go only into the analyst chat, never the trades table — keeps real stats clean.
